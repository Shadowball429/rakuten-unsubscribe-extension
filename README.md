# 楽天市場 メルマガ自動オフ

購入確認画面の「メルマガ配信設定」にあるチェックを自動でオフにする、Manifest V3 のChrome拡張です。ショップからのお知らせ・レビュー依頼メールに対応しています。ビルドや依存パッケージのインストールは不要です。

## インストール

1. Chromeで `chrome://extensions` を開きます。
2. 右上の「デベロッパー モード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. このREADMEと `manifest.json` があるフォルダーを選択します。
5. 楽天市場の購入確認画面を開きます。すでに開いている場合は再読み込みします。

## 動作

- 対象は `https://cart.step.rakuten.co.jp/order-confirmation`（末尾の `/`、クエリパラメーターも可）です。
- 前画面からのSPA遷移に対応するため、スクリプトは `cart.step.rakuten.co.jp` 内の全ページで読み込みます。URLを500ミリ秒間隔で確認し、購入確認画面だけでチェックを操作します。戻る・進む、ページ復元時にもURLを確認します。
- ページ読み込み開始時から監視し、対象がDOMに現れた時点で「すべての選択を解除」ボタンをクリックします。描画前の完了は保証できません。
- 「すべての選択を解除」ボタンの祖先のうち、「メルマガ配信設定」と説明冒頭の「楽天会員情報にご登録されているメールアドレス宛に」を含む最小の枠を特定し、その枠内のチェックボックスを操作します。お気に入りショップ追加や住所・カード保存の設定は対象外です。
- 「全てのお知らせを受け取る」というラベルの画面にも対応しています。
- `checked` と `aria-checked` の両方を確認し、解除が反映されない場合は再試行します。再試行の間隔は最大5秒まで延ばします。状態が食い違う場合も、解除ボタンを使うことでオフのチェックをオンに戻す操作を避けます。
- DOMの差し替えと、プロパティのみの変更を継続して監視します。30秒を超えて初期化・再描画された場合も対応します。オフを確認できた場合はクリックしません。
- 解除ボタンがない従来形式の画面では、オンのチェックボックスを個別にクリックします。
- ユーザーが対象を直接操作した後は、その購入確認画面での自動変更を止めます。別画面への退出を検出してから再入場すると、再び有効になります。
- 外部通信・情報保存・注文確定の操作は行いません。

## 確認と制約

提供された購入確認画面のHTMLを確認し、その構造を再現したテストで検証しています。実際のログイン済み画面での動作は未検証です。楽天側の構造や文言、合成クリックの扱いによって動作しない場合があります。

更新後は `chrome://extensions` でこの拡張の再読み込みボタンを押してから、開いている楽天の購入フローのページを一度再読み込みしてください。それ以降は前画面からの遷移でも動作します。

`tests/browser.html` は模擬DOMの回帰テストです。URL制限をテスト用に差し替えて本体を読み込みます。リポジトリで `python3 -m http.server 8000` を実行し、`http://localhost:8000/tests/browser.html` をChromeで開くと結果を確認できます。

`http://localhost:8000/tests/navigation.html` では、History APIによる前画面からの遷移・退出・戻る・進むを検証します。実際のパスを使用し、オリジンのみテスト用に差し替えています。

実装方式の参考: [Chrome公式 Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)
